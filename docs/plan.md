# 計画：ことづて（AIで動くOSMビューア）

表記：**[事実]** 一次資料かコードで確認、**[報道]** 報道で確認、**[推測]** 推論・調べた範囲での判断、**[未確認]** 確かめられていない。

## 1. 一言で

地図に詳しくない社員が、日本語ひとことで、出典つきの「渡せる地図」をつくる。Googleにも、公開サーバにも頼らずに。

- 社外にも渡せる成果物：出典とデータ時点を焼き込んだ画像、共有リンク。
- 社内用の成果物：GPX、Claudeなしで再実行できるレシピ（行った操作の並びを記録したJSON）。
- 根拠になった OSM の要素IDとデータ時点を示し、タグがなければ「分からない（データなし）」と正直に出す。

## 2. 背景

- 想定する場面（架空）：地図に詳しくない社員が、コースづくり、場所の確認、資料への地図の埋め込みに、一般向けの地図サービスを使っている。
- 使う人は1つの職種に決めない。地図に詳しくない、いろいろな役割の人が使う（2026-11-06 にユーザーが決定）。動画では例ごとに具体的な仕事として見せる（§7）。
- 無償で契約もSLAもないサービスに業務を頼ると、提供条件や規約が変わったときに業務が止まるおそれがある [推測]。
- 以前の推薦は「試走コース・コンパイラ」だったが、ユーザーがビューアへの切り替えを決めた。その後の調査と評価では「ビューアを土台に深い機能を1つだけ主役にする」案も示されたが、4つの操作を均等に作る方針になった。

## 3. 操作の作り込み（4つの操作と、表示の操作）

| 操作 | 作り込み |
|---|---|
| (a) 場所・住所 | 住所はデジタル庁の abr-geocoder で解決し、座標の精度（住居番号の位置／丁目の代表点／町の代表点。応答の `coordinates_level` から作る）を言い換えずに表示する。施設名は OSM で表記ゆれ（name、name:ja、alt_name など）も含めて探し、候補を選ばせる。見つからなければ見つからないと言う |
| (b) 地物の絞り込み | 業務の言葉と OSM タグの辞書を作る。含めるタグと除くタグも辞書に持たせる（例：トンネル＝道路の `tunnel=yes`、建物の通り抜けと暗渠は除く）。画面には「解釈：踏切＝`railway=level_crossing`（歩行者専用は含まない）」のように、どう解釈したかを常に出す。0件は「OSM上で0件（現地にないとは限らない）」 |
| (c) ルート・試走コース | 現在地（ブラウザの位置情報、参照 `here:`）から、寄り先（郵便局やコンビニなど。辞書でタグにし、道の近くの候補から選ぶ）を経由して目的地へ引ける。寄り道で増えた時間を表示する。試走コースは自前の Valhalla で引く。「高速を使わない」はハード除外。合否はルート上の way の生のタグを Overpass で取り直して機械的に判定し、タグがなければ「分からない（データなし）」。トンネルの数え方（連続する `tunnel=yes` を1本、50m未満は除外）を表に明記する。経由地の候補は AI ではなくプログラムが作る（最大5案、ルート計算は最大10回） |
| (d) 資料用の地図・共有 | 出典とデータ時点を焼き込んだ画像。共有リンクは地図の状態をサーバに保存して短いIDで参照する。GeoJSON と GPX にはライセンス情報を埋め込み、社外に渡すときは注意を出す（ODbL の継承条件があるため [事実]） |
| (e) 地図の表示（2026-11-05 に追加） | 拡大・移動・表示の切り替えも日本語で頼める（例：「芝公園のあたりを大きく。郵便局だけ残して」）。場所は (a)(b) の結果の参照で渡し、AI が書いた緯度経度は受け付けない。画面には解釈（場所・表示・残す・隠す）を出す |

| OSMノートの下書き | 確認方法を選ばせ（「Googleマップで見た」は選べない）、社名や「試走」などの語が入っていたら止める。アプリは OSM と通信せず、下書きのコピーまで。投稿は現地を見た本人 |

札（カテゴリ）とボタンは、AI を通さずに手元のサービスへ直接たずねる。いつもの地図アプリと同じように使える。日本語の依頼は、その上に足すもの（2026-11-05 にユーザーが決定）。

Claude API がなくても動くもの、止まるもの（2026-11-06 にユーザーが決定）：

- 動く：地図、5つの札（AIを通さない）、拡大・縮小、現在地、貼った座標への移動（11/7 に追加）、共有リンク、画像と GPX の書き出し（GPX はルートがあるときだけ。画面に GeoJSON のボタンはない）、レシピの再実行（「Claude を使わずに再実行」）。
- 止まる：日本語の新しい依頼。このため、新しい住所の検索、新しいルート、新しい試走コースには Claude が要る。
- 「Claude が止まっても、業務は止まらない」「Claude API が止まっても地図は使えます」は言い過ぎなので使わない。何が動き、何が止まるかを分けて言う。

## 4. 構成

```
日本語の依頼 → Claude（型付きの操作を選ぶ） → 自社のサービスで実行（住所・地物・ルート） → 結果からテンプレートで文章 → 渡せる成果物
```

- 地図：Protomaps の PMTiles（東京の範囲）＋ basemaps-assets を自前配信。MapLibre GL JS。
- 検索：手元の SQLite（osm.db。`npm run setup` か Mac のアプリが作る）。ルート：@valhallajs/valhallajs を同じプロセスで動かす。住所：abrg（ABR の DuckDB）。Mac のアプリ（Electron）は、初めて開いたときにデータを取って作る（11/6〜7。設計書 §16・§17）。
- 前の構成（Docker の Overpass :12345、Valhalla :8002、abr-geocoder :3002）は開発用に残す。`npm run server` で地域の設定（data/region.json）がなければこちら。評価の3回はこの構成で測った。今の構成と結果が同じことは107件の問い合わせで確かめた（`scripts/golden.ts`）。
- Claude API はサーバ側から呼ぶ。MCP サーバは AI を呼ばず、キーも持たない。
- 置き場所（2026-11-06 にユーザーが決定）：1人で使うなら手元の機械、チームなら共有のサーバ。共有のサーバでは前に reverse proxy を置き、`ALLOWED_HOSTS` にその名前を入れる。アプリのサーバ自体は 127.0.0.1 だけで待ち受ける（`src/server/main.ts`）。共有リンクを開けるのは、そのサーバに届く人だけ。届かない人に渡すものは画像。
- 型付きの操作（約12個）：search_place、geocode_address、find_features、route、check_route、set_view、add_pin、highlight、make_share_link、export_png、export_gpx / export_geojson、draft_osm_note。
  - [事実] 11/5 の実装は13個：geocode_address、search_place、find_features、route、set_view、make_share_link、unknown_words、plan_course、check_route、add_pin、export_png、export_route（GPX と GeoJSON）、draft_osm_note。highlight は作っていない（表示の切り替えは set_view）。MCP には draft_osm_note を除く12個を出す。

### 存在しない場所や数を出さない仕組み

- 位置の指定は参照だけ。LLM が覚えている座標は受け付けない。
- Overpass QL は LLM に書かせない。辞書から選んだタグでプログラムが組み立てる。
- 画面の文章はツールの結果からテンプレートで作る。結果にない名前や数字は表示しない。
- 0件、「分からない（データなし）」、辞書にない言葉は、そのとおりに表示する。
- OSM の description、note、fixme など誰でも書ける自由文のタグは LLM に渡さない。

## 5. Claude の使い方

- 実行時：型付きツール。業務の言葉の辞書を1つのファイルにまとめ、検索の組み立て、ツールの選択肢、Skill で共通に使う。MCP の使い道は一括作業（23区の区役所の住所一覧から、ピンと資料用の画像をまとめて作る）。動画では MCP の場面を外し、Claude Code の場面で2秒だけ触れる（§7）。レシピを保存して Claude なしで再実行できるようにする。
- 開発時：hooks（公開サーバのURLを止める、出典表示の検査、型チェックと簡易評価が通るまで終わらせない）、サブエージェント（eval-runner、tag-auditor）、評価セットの先コミット。

## 6. 評価

- 日本語の評価セット40問（各操作10問）。結果が正しいかで採点（住所は正解から100m以内、地物はタグの一致、など）。プロンプト調整の前にコミットする。
- 罠の問い10問（東京の外、存在しない施設、辞書にない言葉）。「見つからない／対応外／「分からない（データなし）」」と正しく答えたか。
- 「AIが座標を作った回数」：成功した操作の入力に、座標らしい数字（`\d{2,3}\.\d{3,}`）があった回数。目標0回。前はここを「捏造の回数（結果にない名前や数字を表示した回数）」と書いていたが、評価が数えているのはそれではない。名前と定義を `eval/README.md` とそろえる（2026-11-06 にユーザーが決定）。
- 改善の記録（3回分）。
- [事実] 分け方（2026-11-05 にユーザーが決定）：40問＝(a)〜(d) 各10問（(e) 表示の操作は (d) に入れる）＋罠10問。評価は3回まで。セットは f799188 でコミットし、プロンプトの調整（47bf364）より前。
- [事実] 結果（`eval/runs/`）：1回目 39/50（78%、M1、機能を足す前）→ 2回目 47/50（94%、評価1回目で落ちた問いを受けた修正（e96db0e：都の境界、画面の外の検索、読めない住所、Claude に渡す画面の状態にルートの有無）と、6つの機能、レビューの修正のあと。SYSTEM プロンプトは未調整）→ 3問だけの調整の試し 3/3 → 3回目 50/50（100%、SYSTEM プロンプトに2行を足したあと）。AIが座標を作った回数は、どの回も0回。全問1回で Claude を138〜141回呼び、約 $0.4、約5分。
- 評価セットは自分たちで作った。100% はこの50問での結果で、ほかの依頼でも同じとは言えない。
- 2つを分けて言う（2026-11-06 にユーザーが決定）：
  - 設計の決まり：画面の文章は、ツールの入力と結果からテンプレートで作る（Claude の自由な文章は出さない。§4）。作りで守るもので、評価で測った数ではない。
  - 測った結果：自作の50問で 78% → 94% → 100%。
- [事実] 評価のスクリプト（`scripts/eval.ts`）は、同じ数に「依頼文にない言葉を『辞書にない言葉』として出した回数」も足している。サーバは `unknown_words` に依頼文にある言葉しか渡さない（`src/server/claude.ts`）。このため、この半分は作りの上で0になり、落ちることがない。
- [事実] 現在地がないまま「今いる場所から」と頼む問いは、評価セットにない。ブラウザの確認（`scripts/check-web.mjs`、3b818e1）で確かめる。
- 使いやすさテスト：11/7 の午前に2人（§8）。

### 冒頭の文（2026-11-06）

- 「明日、Googleマップの商用利用が禁止されたら？」はそのまま使う（仮定と明示）。
- 足す文（ユーザーが承認）：「業務で使ってよい範囲は、ガイドラインに例で書かれているだけ。境目はあいまいで、線を引き直すのも Google。Google Earth の画像は、今も商用には使えない。」
- ユーザーの論点：無料の一般向けの Google マップ（API でも有償の契約でもないもの）には、提供を続ける約束がない（保証の否認、SLA なし）。これを短く言う文として「無料の Google マップには、続ける約束（SLA）がない」を提案した。論点はユーザーのもの。文言はまだ確定していない。
- 根拠（`docs/research/google-map-changes.md`）[事実]：Geo Guidelines は、報告書・提案書・プレゼンなどの業務文書での印刷を認めている。Earth の内容は、商用にも宣伝にも使えない。2006 年の Google マップの規約は、個人の利用を非商用に限っていた（業務の利用は社内に限る）。
- 撮影前に確かめる [未確認]：
  - Geo Guidelines のページが「revenue-generating」（収益を生む利用）を定義しているか。定義していれば「境目はあいまいで」を外す。
  - Google の利用規約の、今の「保証の否認」の文。

### ③ の見せ方（2026-11-06 にユーザーが決定）

- 編集で、解釈の行に「Claudeが読んだ」と付ける。
- 「地図のデータが答えた」は、結果の値（件数、分、◯/×）だけに付ける。条件の確認の条件の列と「辞書にない言葉」には付けない。
- [事実] 解釈の行には操作ごとに番号がつく（8f5a927）。ルートの行には「寄り先：郵便局、手土産」のような項目が出る（ほかに出発、目的地、頼んだ順に寄る：はい）。「種類：」や「いいえ」の項目は出さない。
- 例1の字幕：「ひとことを、Claude が3つの操作に分けた」。

### 例1：現在地から寄り道して客先へ

- 依頼：「今いる場所から、郵便局で書類を出して、手土産を買ってから、港区芝公園4-2-8へ。ルートを共有リンクで」。現在地の許可（`here:`）。
