# ことづて（kotozute）

言葉を託すと、渡せる地図が返ってくる。AI で動く OpenStreetMap（OSM）のビューアです。

## 概要

地図に詳しくない人が、日本語ひとことで、出典つきの「渡せる地図」をつくれるようにしました。使う人は1つの職種に限りません（例は下の「デモの例」）。地図・地物検索・ルート・住所は、お使いの PC の上で動きます。地図の業界に長くいる作者が、Claude Code を開発の中心にして作りました。

「Built with Claude: Japan 2026」（テーマ1「あなたにしかない深さを」）への応募作品です。対応する地域は東京都（島しょ部を除く）です。

## 3つの約束

| 約束 | 中身 |
|---|---|
| ① 言葉から地図へ。はじめてでも、数秒で地図ができる | 作りたい地図を、言葉で伝えるだけです。難しい設定や専門知識は要りません。検索文も OSM のタグも知らなくてよいです。インストールも簡単です |
| ② ローカルファースト。外部に依存しない | 地図、検索、ルート、住所は、お使いの PC の上で動きます。データも手元に置きます。必要な部分だけを手元から読むので、爆速です。地図のサービスの規約が変わっても、急に有料になっても、今の地図は使い続けられます |
| ③ 日本ファースト。日本で使うことを前提に設計 | 住所（丁目・番・号）、駅の名前、平面直角座標、地域メッシュ、度分秒に、追加の設定なしで対応します |

約束の範囲（言い過ぎないための添え書き）：

- **①**：Mac のアプリは .dmg から入れます。署名がないので、初めて開くときは下の「Mac のアプリ」の開き方が要ります。地図のデータの用意は、初めて開いたときだけ約4分かかります（この Mac Studio で測った値）。
- **①**：測った時間は、評価の3回目（50問）で、送ってから答えが届くまで中央値 5.25秒、50問中45問が 8.5秒以内、最長 13.1秒です（Claude を待つ時間を含む。`eval/runs/2026-11-05T13-51-03-359Z.json` の `ms`）。
- **②**：Claude API がなくても動くのは、地図、5つの札、拡大・縮小、現在地、貼った座標への移動、共有リンク、画像と GPX の書き出し（GPX はルートがあるときだけ）、レシピの再実行（「Claude を使わずに再実行」）です。止まるのは日本語の新しい依頼です。新しく住所を調べる、ルートを引く、試走コースを作るには、Claude が要ります。
- **②**：使っているあいだに外に出る通信は Claude API だけです。地図のデータを取るとき（Mac のアプリを初めて開いたときと、「最新にする」を押したとき）だけ、download.geofabrik.de（OSM）、build.protomaps.com（地図）、github.com とその配信先（住所のデータと、ルートの速度表）に通信します。これらが止まっていると「最新にする」は失敗しますが、手元のデータはそのまま使えます。
- **②**：速さはこの Mac Studio で測った値です。札（郵便局 104件）は 26ms、名前の検索は数ms、ルートは 0.3〜0.6秒、2回目からの起動は1秒以内です。前の構成（Docker の Overpass）では、名前の一部での検索に 8〜11秒かかっていました。
- **③**：住所はデジタル庁のアドレス・ベース・レジストリ（ABR）の住居表示で引きます。引ける位置は、ABR に点がある住所なら号の位置、なければ街区の代表点です。たとえばデモの「港区芝公園4-2-8」は街区（芝公園4丁目2）の代表点になります。地番の地域（住居表示をしていない地域）は、町・丁目や市区町村の代表点になることがあります。どの場合も、精度（「座標の精度：街区の代表点」など）を画面に出します。
- **③**：平面直角座標を出すのは東京都（9系）です。読める座標の書き方は下の「日本の座標」にあります。

画面の決まり：

- Claude がするのは、依頼の言葉を読んで、操作（ツール）と入力（辞書の言葉、場所の参照、住所や施設名の文字、条件の数（例：トンネル2本、60分以内））を選ぶことです。入力は「解釈」の行に出します。
- 結果の値（見つかった名前、件数、かかった分、◯/×）は、地図のデータ（OSM、ABR）とツールの結果から来ます。画面の文章は、ツールの入力と結果からテンプレートで作ります。Claude の自由な文章は画面に出しません。
- 0件は「OSM上で0件（現地にないとは限らない）」、タグがなければ「分からない（データなし）」とそのまま出します。

AI に任せないこと：

- 場所は参照（`abr:N`、`result:N`、`osm:way/…`、`click:N`、`here:`）だけで指します。AI が書いた緯度経度は受け付けません。
- 検索の条件は AI に書かせません。辞書から選んだタグと範囲で、プログラムが組み立てます。範囲の面積、件数、時間に上限があります。
- 貼った座標は Claude に渡さず、画面の中で読みます。
- 操作の入力は、サーバが型（zod）で検証します。

## 何ができるか

| 操作 | できること |
|---|---|
| (a) 場所・住所 | 住所を ABR で調べ、座標の精度（住居番号の位置、街区の代表点など）をそのまま出す。施設や駅は OSM の名前で探す。「品川駅」のように「〜駅」で探して駅が見つかれば、駅だけを返す（OSM の駅の名前は「品川」）。「霞ヶ関駅」と「霞ケ関駅」のような、ヶ・ケ・が の書き分けも探し直す |
| (b) 地物の絞り込み | 郵便局、手土産、コンビニ、踏切、トンネルなど13語を、辞書で OSM のタグにして探す。どう解釈したかを毎回出す（例：「踏切＝railway=level_crossing（歩行者用の踏切（railway=crossing）は含まない）」） |
| (c) ルート・試走コース | 現在地から、郵便局やコンビニに寄って目的地へ。寄り道で増えた時間を出す。試走コース（例：トンネル2本、高速なし、60分以内）は、経由地の候補をプログラムが作り、通った道の OSM のタグで「条件の確認」を作る。タグがなければ「分からない（データなし）」 |
| (d) 資料用の地図・共有 | 共有リンク、出典とデータ時点を焼き込んだ画像、GPX・GeoJSON（社内確認用。ODbL の注意つき）、ピン |
| (e) 地図の表示 | 「芝公園のあたりを大きく。郵便局だけ残して」のように、移動・拡大・表示の切り替えも日本語で頼める |

このほか：

- **札とボタン**：検索の横の札（郵便局・手土産・コンビニ・踏切・トンネル）と右下のボタン（現在地・拡大・縮小）は、AI を通さずに手元のサービスへ直接たずねます。
- **日本の座標**：下の節。
- **レシピ**：行った操作の並びを保存し、Claude を使わずに同じ順で再実行できます。
- **外部通信の記録**：操作のたびに、サーバが出した通信を「自分のサービス」「api.anthropic.com」「その他の外部」に分けて数えて見せます。
- **OSM ノートの下書き**：地図の誤りに気づいたら、OSM のノートの下書きを作ります。確認方法は本人が選び（「Googleマップで見た」は選べない）、会社を表す語や「試走」などが入っているとコピーできません。アプリは OSM と通信しません。投稿は現地を見た本人が手で行います。
- **MCP**：同じ操作を MCP のツールとしても使えます（`docs/mcp.md`）。

### 日本の座標

- 地図をクリックした点と、地点の詳細（「座標」を開く）に、緯度経度、度分秒、平面直角座標（JGD2011。東京は9系）、3次の地域メッシュ（8桁）を出します。値は地図の位置から計算したもので、測量の値ではありません。
- 検索の欄に座標だけを貼ると、AI を通さずにその場所へ動きます。読める書き方：
  - 10進の緯度経度（`35.681236, 139.767125`。経度が先でもよい）
  - 度分秒（`北緯35°40′52.4″ 東経139°46′01.6″`、`35度40分52秒 139度46分2秒`）
  - 北緯・東経や N・E の付いた10進（`北緯35.681236 東経139.767125`、`N35.681236 E139.767125`）
  - 平面直角座標（`9系 X=-35363.24 Y=-5992.92`。系はローマ数字（`第Ⅸ系`）でもよい。東京では系を省ける。そのときは X=・Y= を付けるか、マイナスの付いた数で書く。X=・Y= がなければ X（北）、Y（東）の順に読み、どう読んだかを札の題に出す）
  - 地域メッシュ（4桁・6桁・8桁。`5339-46-11` のようにハイフンがあってもよい。中心へ動く）
  - 全角の数字と記号、かな入力の「ー」も読みます。
  - 日本の外の緯度経度は、Claude に送らずに「日本の範囲の外の座標です」と出します。
- 計算は画面の中だけで行います（国土地理院の式。1〜19系。地域メッシュは JIS X 0410）。国土地理院の計算の値と 1mm 以内で合うことを `scripts/check-quick.ts` で確かめています。

デモの例1（想定：郵便局と手土産の店に寄って客先へ行く人）：「今いる場所から、郵便局で書類を出して、手土産を買ってから、港区芝公園4-2-8へ。ルートを共有リンクで」。
デモの例2（想定：条件つきのコースを作る人）：品川駅を出て品川駅に戻る試走コース（トンネル2本、高速なし、60分以内）。

## Mac のアプリ

コマンドを使わずに入れられる Mac のアプリ（.dmg）があります。

- **対応**：Apple Silicon の Mac だけです。確かめたのは、この Mac Studio（M5 Ultra、96GB、macOS 27.0.1）だけです。
- **入れ方**：.dmg（約216MB）を開いて、ことづてをアプリケーションに入れます。
- **署名**：Apple の Developer ID の署名も公証もありません（ad-hoc の署名だけ）。ダウンロードしたものを初めて開くと、macOS が止めます。「システム設定 → プライバシーとセキュリティ」の下に出る「このまま開く」を押すと開けます。
- **初めて開いたとき**：
  1. Claude API のキーの画面が出ます。キーはキーチェーン（safeStorage）で暗号化して保存します。キーなしでも、地図・札・ボタンは使えます。
  2. 「地図のデータ」の画面が出ます。地図のデータはアプリに入っていません。アプリが取って、手元で作ります。取るのは約0.7GB（OSM の関東 約500MB を Geofabrik から、地図 約190MB を Protomaps から、住所のデータ 約22MB を GitHub から）です。
  3. この Mac では、押してから地図が出るまで約4分（252秒）でした。そのうち OSM のダウンロードが153秒（約3.4MB/s。回線の速さによる）、作るのが約100秒です。作ったあとに残るのは約1.5GB です。作るあいだは最大約4.2GB を使うので、ディスクの空きが約5GB 要ります。作るときのメモリは最大約3.8GB です。
- **2回目から**：約1秒で地図が出ます。
- **使っているときのメモリ**：アプリの全部のプロセスの合計で、地図を出したとき約0.8GB、ルートを引いたあと約1.3GB でした。
- **地図のデータを新しくする**：メニューの「地図のデータ…」→「最新にする」。作るあいだは前のデータで使えます。できたら切り替えます。失敗したら前のデータのままです。
- **データの置き場所**：`~/Library/Application Support/kotozute/`（共有リンク、レシピ、操作の記録、キー、地図のデータ）。
- **OSM ノートで止める語**（社名など）：メニューの「OSM ノートで止める語…」で開くファイル（`note-block-words.txt`）に、1行に1語で書きます。書いたらアプリを開き直します。`npm start` では `.env` の `NOTE_BLOCK_WORDS`（カンマ区切り）に書きます。
- 地域は東京都だけです。

## 1つのコマンドで動かす（開発する人向け）

Node 24 以上が要ります。リポジトリの直下で：

```bash
npm install
```

```bash
npm run setup -- --region=tokyo
```

```bash
npm start
```

ブラウザで http://localhost:8787 を開きます。日本語の依頼を使うときは、`.env` に `ANTHROPIC_API_KEY` を書きます。

- 地域は `tokyo`、`japan`、Geofabrik の日本の8地方、47都道府県から選べます。確かめたのは東京だけです。
- `npm run setup` は、OSM の pbf を TypeScript で読んで検索データ（SQLite）を作り、ルートのデータ（Valhalla のタイル）、地図の切り出し、住所のデータ（abrg の DuckDB）を作ります。住所の道具（abrg）は Go でビルドするので、Go と C のコンパイラが要ります（Mac は `xcode-select --install`）。住所のデータを一から作るときだけ Docker を使います。osmium は、東京以外の境界を作るときだけ使います。
- `npm run setup` が取りに行く先は、設計書（`docs/superpowers/specs/2026-11-06-one-command-setup-design.md` の §3）にあります。実行時に外に出るのは Claude API だけです。
- 確かめ方（`scripts/check-*.ts`、`scripts/check-web.mjs`）は `docs/HANDOFF.md` にあります。

### どこで動かすか

- **1人で使う**：自分の機械で動かし、http://localhost:8787 を開きます。
- **チームで使う**：共有のサーバで動かします。アプリのサーバは 127.0.0.1 だけで待ち受けるので、前にリバースプロキシを置きます。そのホスト名を環境変数 `ALLOWED_HOSTS`（カンマ区切り）に書きます。書いていないホスト名からの API は断ります（403）。ブラウザの位置情報（現在地）は HTTPS か localhost でないと使えないので、プロキシは HTTPS にします。
- 共有リンクを開けるのは、そのサーバに届く人だけです。届かない人に渡すものは画像です。

## 構成

```
ブラウザ、または Mac のアプリの窓（MapLibre GL JS。札・ボタン・日本語の依頼・貼った座標）
   │  このサーバとだけ話す
   ▼
アプリのサーバ（Hono、127.0.0.1）
   ├─ 札・ボタン ──────────────┐
   ├─ 日本語の依頼 → Claude API（ツールを選ぶ）※ 外に出るのはここだけ
   │                           ▼
   │                  操作の一覧（src/ops、zod で検証、操作ログ）
   │                           ├─ 検索：手元の SQLite（osm.db。node:sqlite）
   │                           ├─ ルート：Valhalla を同じプロセスで（@valhallajs/valhallajs）
   │                           └─ 住所：abrg（ABR の DuckDB。127.0.0.1 の空いたポート）
   └─ 地図ファイル（PMTiles）・フォント・アイコンの配信（自前）

MCP サーバ（stdio）─→ 同じ操作の一覧（AI を呼ばない、キーを読まない）
```

- 日本語の依頼に使うモデルは `claude-sonnet-5-5`（`src/server/claude.ts`）。キーはサーバの環境変数 `ANTHROPIC_API_KEY`（`npm start` は `.env` から、Mac のアプリはキーチェーンから）で渡し、ブラウザには置きません。
- 開発用の `npm run server` は、地域の設定（`data/region.json`）がなければ、前の構成（Docker の Overpass :12345、Valhalla :8002、abr-geocoder :3002）を使います。評価の3回（11/5）は、この前の構成で測りました。前の構成と今の構成で、操作の結果が同じになることを、107件の問い合わせで確かめています（`scripts/golden.ts`）。

## 評価

日本語の依頼を本物の Claude に渡し、選んだ操作と結果をプログラムで採点します（`eval/README.md`）。

設計の決まりと、測った結果を分けて書きます。

- **設計の決まり**：画面の文章は、ツールの入力と結果からテンプレートで作ります。Claude の自由な文章は出しません（上の「画面の決まり」）。これは作り方の決まりで、評価で測った数字ではありません。
- **測った結果**：自作の50問で 78% → 94% → 100% でした（下の表）。

評価セットについて：

- 50問：(a)〜(d) 各10問（(e) 表示の操作は (d) に入れる）と、罠10問（東京都の外、存在しない施設、辞書にない言葉、座標の指定、0件）。
- 正解の座標は、ABR の結果を使わずに OSM の要素など別のデータで決めています。
- **評価セットは自分たちで作ったものです。** 100% はこの50問での結果で、ほかの依頼でも同じとは言えません。
- 評価セットは、プロンプトを調整する前にコミットしました（cafb4a3）。調整は ceafe28 です。
- 3回とも 11/5 に、前の構成（Docker の Overpass、Valhalla、abr-geocoder）で測りました。そのあと、検索の「〜駅」と ヶ・ケ・が の扱いを直しました（11/7）。この直しのあとは、評価を回していません（回すのは3回までと決めているため）。
- 現在地がないときの依頼を扱う問いは、評価セットにありません。この場合は画面の確認（`scripts/check-web.mjs`）で確かめています。

| 回 | 何のあと | 正答 | AIが座標を作った回数 | 費用 |
|---|---|---|---|---|
| 1 | 4つの操作が一通り動いた時点（M1） | 39/50（78%） | 0回 | $0.38 |
| 2 | 評価1回目で落ちた問いを受けた修正（821586f：都の境界、画面の外の検索、読めない住所、Claude に渡す画面の状態にルートの有無）と、試走コース、ピンと書き出し、レシピ、ノート、MCP の6つの機能、レビューの修正のあと。SYSTEM プロンプトは未調整 | 47/50（94%） | 0回 | $0.43 |
| 3 | SYSTEM プロンプトに2行を足したあと（頼まれていない地物を足さない。0件なら名前を言い換えて探し直さない） | 50/50（100%） | 0回 | $0.42 |

「AIが座標を作った回数」は、成功した操作の入力に座標らしい数字（`\d{2,3}\.\d{3,}`）があった回数です。採点のスクリプトは、依頼文にない言葉を「辞書にない言葉」として出した回数も同じ数に足します。ただしサーバが依頼文にない言葉を落としてから操作に渡すので（`src/server/claude.ts` の `quoted`）、こちらは作りの上で0回にしかなりません。2回目と3回目の間に、落ちた3問だけで調整を試しました（3/3）。結果のファイルは `eval/runs/` にあります。

```bash
npx tsx scripts/eval.ts
```

`.env` のキーが要ります。検索は地域の設定（`data/region.json`）があれば手元の SQLite、なければ Overpass :12345 を使います。ルートは Valhalla :8002（`VALHALLA_MODE=embedded` と `VALHALLA_CONFIG` で組み込み）、住所は `ABR_URL`（既定は :3002）です。1回で Claude を約140回呼び、約 $0.4、約5分かかります。`--only a01,b03` や `--group trap` で一部だけ回せます。

## Claude Code の使い方

開発は Claude Code が中心です。目的ごとに次のものを使いました。

| 仕組み | 何のため | 場所 |
|---|---|---|
| CLAUDE.md | 決定事項と、実行時に守るルール（公開サービスを呼ばない、座標を受け付けない、検索文を AI に書かせない、など） | `CLAUDE.md` |
| PreToolUse hook | 開発中に、Google の地図やフォント、公開 Overpass、公開 CDN などのホスト名を含む書き込みと取得を、理由をつけて止める。止めた記録は `logs/hook-blocks.jsonl` に追記する（今は7件。Google のフォント配信が5件、Google が2件） | `.claude/hooks/block-public.mjs` |
| Stop hook | 型チェックと速い検査（評価セットの形、書き出しの出典表示、辞書の色と解釈、日本の座標の計算）が通るまで作業を終わらせない | `.claude/hooks/stop-checks.mjs`、`scripts/check-quick.ts` |
| サブエージェント eval-runner | 評価を回し、前回と比べて報告する。お金がかかるので、承認があるときだけ回す | `.claude/agents/eval-runner.md` |
| サブエージェント tag-auditor | 辞書の言葉が関東の OSM データに何件あるかを数え、0件や少ない言葉の直し方の案を出す | `.claude/agents/tag-auditor.md`、`scripts/tag-audit.ts` |
| Skill kotozute-dictionary | 辞書に言葉を足す・直すときの手順と決まり | `.claude/skills/kotozute-dictionary/SKILL.md` |
| ワークフローと並行の worktree | 11/5 に、6つの作業（試走コース、ピンと書き出し、レシピと外部通信の記録、OSM ノート、MCP、開発用の部品）を別々の worktree で並行して作り、1つにまとめた。11/6〜7 も、セットアップと Mac のアプリの作業を同じ形で並行して作った。作ったものは別のエージェントがレビューし、指摘を確かめてから直した | 11/5 の6つの作業は 5828ba3、d4b96aa、f5c3bfc、fc70f9d、9c82251、f0bac95 |
| 評価の順番 | 評価セットをプロンプトの調整より前にコミットし、評価の結果も1回ずつコミットした | cafb4a3 → 2c9102a → 821586f → 2be320c → ceafe28 |

hooks が効くのは開発中の Claude Code だけです。アプリの実行時の通信は、アプリのコード（外部通信の記録）で見せます。

## MCP

画面と同じ操作を、Claude Desktop や Claude Code から MCP のツールとして使えます。たとえば23区の区役所の住所23件をまとめて住所にし、精度ごとに数えて、共有リンクにできます。MCP サーバは AI を呼ばず、Claude API のキーも読みません。つなぎ方は `docs/mcp.md` にあります。

## 知っている問題

- Mac のアプリは署名も公証もないので、初めて開くときに macOS が止めます（開き方は上の「Mac のアプリ」）。
- Mac のアプリは Apple Silicon だけです。Intel の Mac、Windows、Linux では試していません。
- 住所のデータ（GitHub Releases の `abr-tokyo-20261106`）は、リポジトリを公開するときに上げます。上げる前は、Mac のアプリの初めてのデータ作りが「住所のデータ」の手順で止まります。
